# Metacrawl

A Metacritic games service that crawls game listings, fetches critic and user
reviews, generates AI-written summaries per review kind, and serves a
browsable web UI with search, filtering, and text-similarity recommendations.

## Architecture

```
FastAPI web app (Jinja2 + HTMX)
  ├── GET /             — paginated game list, search, platform filter
  ├── GET /games/:slug  — detail page: scores, summaries, similar games
  ├── GET /health       — liveness (always 200)
  ├── GET /health/ready — readiness (503 when LLM unreachable)
  └── POST /api/crawl/run — trigger crawl (requires X-Crawl-Secret header)

Crawler (background thread via CrawlWorker)
  ├── Finder API  → upsert game metadata + platform scores
  ├── Detail page → description, genres, video, developer/publisher
  ├── Reviews     → critic (score-sorted) + user (thumbs_up-sorted)
  ├── LLM         → two summaries per game (critic + user kind)
  └── Embedder    → text embedding for similarity search

Storage: SQLite  (6 tables: games, platform_scores, game_genres,
                  reviews, summaries, embeddings, crawl_runs)
Seed:    seeds/seed.json — 172 games, 268 summaries pre-loaded at boot
```

**LLM summary contract:** the model returns `{"likes": "...", "dislikes": "..."}`.
Either field may be JSON `null` when a side genuinely has nothing — e.g. a game
with only uniformly negative reviews gets `likes: null`, and the card shows
"No positives mentioned across N reviews" instead of a blank heading.

## Robots.txt position

Metacritic's `robots.txt` does not block the paths we access.  We additionally:
- identify with a descriptive `User-Agent` string in every request
- rate-limit to 1 request/second (configurable via `MC_RATE_LIMIT_RPS`)
- disk-cache all responses with 1-hour TTL and `If-Modified-Since` revalidation

## LLM provider

**Production:** Groq — `llama-3.3-70b-versatile` (131 072-token context window,
production status as of 2026-10).  Set `MC_LLM_API_KEY` in the Render dashboard.
Prompt is capped at 25 reviews × 1 200 chars each to stay well inside free-tier
token-per-minute limits.

**Local dev:** Ollama — `qwen2.5:7b` by default.  Run `ollama serve` and
`ollama pull qwen2.5:7b` before running the backfill.

## Deployment (Render free tier)

```bash
# One-time: push to GitHub and connect repo in Render dashboard
# render.yaml drives the rest: Docker build, healthCheckPath /health,
# autoDeploy on main, MC_SCHEDULER_ENABLED=false

# Set these secrets in the Render dashboard (never committed):
#   MC_LLM_API_KEY   — Groq API key (gsk_...)
#   MC_CRAWL_SECRET  — auto-generated by Render (also add as GitHub Actions secret CRAWL_SECRET)

# GitHub Actions scheduled workflow triggers the hourly crawl:
#   POST https://<service>.onrender.com/api/crawl/run
#   X-Crawl-Secret: <MC_CRAWL_SECRET value>
```

On the free plan, the disk add-on is unavailable and the DB resets on each
restart.  `restore_if_empty()` reseeds from `seeds/seed.json` automatically,
so the service always starts with data.

## Running locally

```bash
# Install dependencies
pip install -r requirements.txt

# Start Ollama (for LLM + embeddings)
ollama serve &
ollama pull qwen2.5:7b
ollama pull nomic-embed-text

# Crawl + summarise
PYTHONPATH=src python -m metacrawl.crawl --source scored --pages 10
PYTHONPATH=src python -m metacrawl.backfill --limit 100

# Web server
PYTHONPATH=src python -m metacrawl.web     # http://localhost:8000

# Tests (offline, no network required)
PYTHONPATH=src python -m pytest tests/
```

## What does not work yet

- **Embeddings disabled in production** — Groq serves chat completions only,
  so `MC_EMBED_PROVIDER` is left empty in `render.yaml`.  Games added by the
  hourly crawl fall back to metadata-overlap similarity (weighted Jaccard:
  genres 60 %, platforms 40 %).  The UI labels each result with the method
  used ("embedding" or "metadata overlap") so the degradation is visible.

- **Ephemeral database on the free host** — Render's free plan has no
  persistent disk.  Every restart restores the committed seed, so crawl
  results added after deploy do not survive a restart.  The seed is rebuilt
  locally and recommitted to update production data.

- **`mafia-the-old-country-man-of-honor` user summary** — local Ollama returns
  HTTP 500 when generating the user summary for this game.  The failure is not
  reproducible by sending the same prompt directly to Ollama; root cause
  unidentified.  The critic summary is present; the user summary is absent and
  recorded as an `llm_error`.

- **Hourly crawl uses an external scheduler** — Render free instances spin down
  after 15 minutes of inactivity, so an in-process APScheduler job cannot
  fire.  Instead, `MC_SCHEDULER_ENABLED=false` disables APScheduler and a
  GitHub Actions scheduled workflow in this repo sends a signed
  `POST /api/crawl/run` request each hour.  This wakes the instance and
  triggers the crawl.

- **Video playback** — `video_url` is stored but no player is rendered in the UI.
