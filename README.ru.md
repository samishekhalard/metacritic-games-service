# Metacrawl

Сервис игр Metacritic: собирает данные о играх, рецензии критиков и пользователей,
генерирует AI-резюме и предоставляет веб-интерфейс с поиском, фильтрацией по
платформе и рекомендациями на основе текстового сходства.

---

## Живое демо

**https://metacrawl.onrender.com**

Сервис отображает постраничный каталог игр с оценками Metascore, обложками,
таблицами оценок по платформам, AI-резюме рецензий критиков и пользователей,
а также блоком «похожие игры» на основе текстовых эмбеддингов или
пересечения жанров и платформ. Если бесплатный инстанс Render успел
«заснуть», первый запрос может занять около 50 секунд.

## Быстрый старт

### Docker

```bash
docker build -t metacrawl .
docker run -p 8000:8000 \
  -e MC_LLM_BASE_URL=https://api.groq.com/openai/v1 \
  -e MC_LLM_API_KEY=gsk_... \
  -e MC_LLM_MODEL=llama-3.3-70b-versatile \
  -e MC_CRAWL_SECRET=change-me \
  metacrawl
```

При первом запуске приложение автоматически загружает данные из `seeds/seed.json`;
сервис доступен на `http://localhost:8000`.

### Локальная разработка

```bash
pip install -r requirements.txt

# Запуск Ollama для локальных LLM и эмбеддингов
ollama serve &
ollama pull qwen2.5:7b
ollama pull nomic-embed-text

# Веб-сервер (при первом запуске сид загружается автоматически)
PYTHONPATH=src python -m metacrawl.web        # http://localhost:8000

# Запуск краулера
PYTHONPATH=src python -m metacrawl.crawl --source scored --pages 5

# Бэкфилл обложек и AI-резюме для новых игр
PYTHONPATH=src python -m metacrawl.backfill

# Тесты
make test          # 173 юнит-теста
make e2e           # 27 Playwright-тестов (требуется сервер на localhost:8000)
```

Необходимые переменные окружения:

| Переменная | Назначение | По умолчанию |
|------------|-----------|--------------|
| `MC_LLM_BASE_URL` | OpenAI-совместимый эндпоинт | `http://localhost:11434/v1` |
| `MC_LLM_API_KEY` | API-ключ провайдера LLM | `ollama` |
| `MC_LLM_MODEL` | Название модели | `qwen2.5:7b` |
| `MC_CRAWL_SECRET` | Общий секрет для `POST /api/crawl/run` | *(не задан = эндпоинт закрыт)* |
| `MC_EMBED_PROVIDER` | Включить эмбеддинги (`ollama` или `openai-compatible`) | *(не задан = отключено)* |

## Архитектура

```
Краулер (фоновый поток)
  │
  ├── Finder API        → метаданные игры, оценки по платформам (upsert)
  ├── Detail API        → описание, жанры, видео, разработчик/издатель
  ├── Reviews API       → рецензии критиков (по оценке) и пользователей (по лайкам)
  ├── LLM               → два резюме на игру: вид «critic» + вид «user»
  └── Embedder          → текстовый эмбеддинг: название + описание + жанры

Хранилище
  └── SQLite (games, platform_scores, game_genres, reviews, summaries,
              embeddings, crawl_runs)

Веб (FastAPI + Jinja2 + HTMX)
  ├── GET /                    каталог игр: пагинация, поиск, фильтр платформы, сортировка
  ├── GET /games/:slug         страница игры: оценки, резюме, рецензии, похожие игры
  ├── GET /games/:slug/similar HTMX-фрагмент — похожие игры (эмбеддинг или пересечение)
  ├── GET /img/:id             прокси обложек (LRU-кеш на диске, SVG-плейсхолдер при ошибке)
  ├── GET /health              проверка работоспособности — всегда 200, статистика
  ├── GET /health/ready        проверка готовности — 503 если LLM недоступен
  └── POST /api/crawl/run      запуск краулера (HMAC-токен из UI, общий секрет для cron)
```

## Источники данных

Фронтенд Metacritic — это серверно-рендеренное приложение на Nuxt 3. Вместо
парсинга HTML сервис напрямую обращается к тому же бэкенд JSON API, который
использует сам Nuxt для гидратации страниц. Поскольку краулер не зависит от
CSS-классов или структуры DOM, косметические редизайны его не ломают.

**Формат devalue.** Данные страницы сериализованы в формате
[devalue](https://github.com/Rich-Harris/devalue): плоский массив, где объекты
представлены целочисленными индексами, а специальные значения кодируются
отрицательными целыми сентинелями (`-1` для `undefined`, `-2` для `Infinity`
и т.д.). Краулер декодирует этот формат без импорта npm-пакета, обходя граф
индексов и восстанавливая исходное дерево объектов.

**Обложки игр.** Изображения обложек отсутствуют в JSON-ответе API — они
встречаются только в серверно-рендеренном HTML в атрибуте `<img srcset>`.
Путь в CDN содержит 40-символьный хеш содержимого, кодирующий точные
параметры ресайза; тот же хеш с другими параметрами запроса вернёт 403.
Даже при правильно сформированном URL прямые запросы изображений с другого
источника отклоняются: CDN требует заголовки `Referer: https://www.metacritic.com/`
и `Accept: image/*`. Чтобы не отображать сломанные изображения, каждая
обложка проксируется через `GET /img/{game_id}`: сервис сам запрашивает
изображение с нужными заголовками, кеширует результат на диске (LRU, с
ограничением по количеству файлов и суммарному размеру) и возвращает
SVG-плейсхолдер — инициалы названия игры на цвете, производном от заголовка —
при любой ошибке или отсутствии URL. Шаблоны никогда не ссылаются на
`metacritic.com` напрямую; это проверяется юнит-тестом, сканирующим все
`.html`-файлы.

## Позиция по robots.txt

`metacritic.com/robots.txt` запрещает доступ к `/search`, `/signup`, `/login`,
`/user`, `/jl/`, `/8264/` и `/7336/`. Ни один из этих путей сервис не
затрагивает. В том же файле перечислены и явно заблокированы по имени строки
User-Agent нескольких AI-краулеров.

Принятый подход: честный User-Agent в каждом запросе, 1 запрос в секунду
(настраивается через `MC_RATE_LIMIT_RPS`), все ответы кешируются на диске
с TTL 1 час, ничего за аутентификацией. Сервис читает публично доступные
оценки и рецензии — ту же информацию, что видит любой браузер.

## Что было измерено

Сид был построен локально с помощью Ollama и поставляется вместе с
репозиторием, поскольку бесплатный хост Render не предоставляет
постоянного диска — каждый рестарт восстанавливает данные из
`seeds/seed.json`.

| Метрика | Значение |
|---------|----------|
| Игр в поставляемом сиде | 172 |
| Игр с резюме и критиков, и пользователей | 100 |
| Игр с одним резюме (критиков или пользователей) | 67 |
| Рецензий сохранено | 2 712 |
| Эмбеддингов в сиде | 171 |
| Юнит-тестов проходит | 173 |
| Playwright E2E-тестов проходит | 27 |

Резюме сгенерированы локально с помощью **qwen2.5:7b** через Ollama.
Эмбеддинги сгенерированы локально с помощью **nomic-embed-text** через Ollama.
Продакшн LLM: **llama-3.3-70b-versatile** на бесплатном тарифе Groq.

## Архитектурные решения

**Эфемерная база данных с поставляемым сидом.** Бесплатный тариф Render не
предоставляет постоянного диска. Вместо того чтобы требовать подключения
базы данных, приложение поставляется с JSON-сидом из 172 обработанных игр,
который загружается автоматически при пустой таблице `games`. Сид пересобирается
локально и коммитится для обновления продакшн-данных. Компромисс: данные,
добавленные краулером после деплоя, не переживают рестарт.

**Внешний планировщик вместо внутрипроцессного cron.** Бесплатный инстанс
Render засыпает после 15 минут бездействия, поэтому задание APScheduler
внутри процесса не может срабатывать по расписанию. `MC_SCHEDULER_ENABLED=false`
отключает внутренний планировщик. GitHub Actions workflow
(`.github/workflows/crawl.yml`) отправляет подписанный `POST /api/crawl/run`
каждый час, тем самым и пробуждая инстанс. Отдельное задание с интервалом
10 минут пингует `/health`, чтобы инстанс не засыпал между краулами.

**Резюме пропускаются, никогда не придумываются.** Игра без рецензий не
получает резюме. Игра с исключительно негативными рецензиями хранит `null`
в поле `likes`, а карточка показывает «No positives mentioned across N reviews»
вместо пустого заголовка. Каждое поле может быть null независимо.

**Ошибки считаются, а не замалчиваются.** Каждый запуск краулера фиксирует
`llm_errors` и `embed_errors` вместе с `games_created`. Эти данные доступны
через `/health` и видны без чтения логов.

**Двойная аутентификация краулера.** `POST /api/crawl/run` принимает либо
HMAC-токен (сгенерированный на сервере, встроенный в `hx-headers` кнопки UI,
действующий 5 минут), либо заголовок с общим секретом (`X-Crawl-Secret`) для
программных клиентов, таких как GitHub Actions. Сам секрет никогда не
попадает в браузер.

## Тестирование

**173 юнит-теста** охватывают краулер, парсер payload, прокси изображений,
экспорт/импорт сида и веб-маршруты. Они работают офлайн — без сетевых
запросов и без запущенного сервера.

**27 Playwright E2E-тестов** (`make e2e`) управляют реальным браузером
Chromium против живого сервера. Набор читает `BASE_URL` из переменной
окружения и работает одинаково против `localhost:8000` и
`https://metacrawl.onrender.com`. Примечательные проверки:

- Изображения тестируются на `naturalWidth > 0`, а не просто на наличие
  элемента `<img>` — это выявляет сбои прокси и сломанные URL CDN, которые
  проверка HTML-разметки пропустила бы.
- Количество игр на странице каталога должно совпадать с `db.games` из `/health`.
- Сортировка по заголовку проверяется без учёта регистра (стандартная бинарная
  сортировка SQLite ставит заголовки в верхнем регистре перед заголовками в
  смешанном; исправление использует `COLLATE NOCASE`).
- Ни один шаблон не должен содержать URL `metacritic.com` (проверяется
  юнит-тестом, сканирующим все `.html`-файлы в директории шаблонов).

## Что пока не работает

**Эмбеддинги отключены в продакшне.** Groq предоставляет только чат-комплишны;
`MC_EMBED_PROVIDER` не задан в `render.yaml`. Игры, добавленные почасовым
краулером, используют резервный алгоритм — пересечение метаданных (взвешенный
коэффициент Жаккара: жанры 60%, платформы 40%). UI отображает метод для каждого
результата («embedding» или «metadata overlap»), поэтому деградация видна.

**Эфемерная база данных.** Каждый рестарт Render восстанавливает поставляемый
сид. Данные краулера, накопленные между деплоями, теряются при следующем
рестарте. Это известное следствие подхода без постоянного диска.

**Резюме пользователей для `mafia-the-old-country-man-of-honor`.** Локальный
Ollama возвращал HTTP 500 при генерации пользовательского резюме для этой игры.
Ошибка не воспроизводится при отправке того же промпта в Ollama напрямую;
причина не установлена. Резюме критиков присутствует; резюме пользователей
отсутствует и учтено как `llm_error` в записи о запуске краулера. Никаких
предсказаний о других провайдерах не делается.

**Расписание GitHub Actions.** Запланированные workflow могут запускаться с
опозданием из-за очереди GitHub. Они также автоматически отключаются через
60 дней неактивности репозитория; репозиторий должен получить коммит, или
workflow нужно включить вручную.

**Опциональная задача 1 (транскрипция YouTube Let's Play) не реализована.**
